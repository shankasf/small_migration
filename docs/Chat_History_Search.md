# Chat history search

The chatbot can discover past migration discussions through `search_chat_history` and uploaded/generated files through `search_chat_files`. It searches the current chat first and can expand to the authenticated user's other chats. For a correction such as “no, from the chat,” the instructions retain the earlier topic rather than searching the literal correction or switching to GitHub.

History search combines PostgreSQL full-text ranking with pgvector cosine similarity using the existing screened embedding service. It searches message text and live attachment/output filenames. Results contain the source chat, message ID, timestamp, role, excerpt, and available file references. A filename mentioned by an assistant is a claim, not proof that a file was attached; the instructions require that distinction. Discovery does not require manual file selection. Processing a discovered file still uses the existing exact-version attachment flow.

`MessageSearchChunk` is a rebuildable index. The background worker backfills existing transcripts and indexes new messages, retries embedding failures with backoff, and screens text before embedding. Queries also search unindexed messages immediately with keyword matching, including content beyond the first chunk. Results expose embedding availability and whether the semantic index is complete. Original messages and files remain retained; this feature adds no scheduled deletion.

The internal endpoint requires the shared service key and rechecks active user status and current-chat ownership. All retrieval is restricted to that user's sessions, including for administrators. Attachment metadata is resolved with live source ownership checks. Queries and results pass through the content policy boundary, and searches emit audit events. User identity and current session are bound by the backend/agent turn, not supplied as model tool arguments.

Deployment needs the additive `prisma/sql/chat-search.sql` schema, included in `scripts/preflight-security-schema.py`, and the new backend and AI-service versions. Index backfill begins after startup. Keyword retrieval is available while embeddings catch up. Existing full current-thread history continues to be sent, now with authorized saved attachment metadata.

Validation: `services/backend/tests/chatSearch.test.ts` exercises real PostgreSQL/pgvector queries with a deterministic embedding mock, covering paraphrases, older/unindexed/long messages, scope and ownership, references, legacy/generated files, pagination, screening, retry, source deletion and internal authentication. `services/ai-service/tests/test_chat_search_tools.py` verifies tool registration, bound identity, response screening and source-selection instructions. These tests establish retrieval plumbing; they do not measure live-provider relevance or prove deployed behavior.
